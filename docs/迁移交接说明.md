## 4. Linux 环境和最短启动流程

既有环境为 **Ubuntu 24.04 虚拟机（VMware）**。代码按 ROS 2 Jazzy 和 Gazebo Sim 的 `gz sim` / `ros_gz` 接口编写；进入新环境后应核实实际安装情况，不能假定 Windows 带来的文件等于 Linux 已装好依赖。

此前用户遇到高频闪烁和画面卡死，反馈以下组合有效：

```bash
QT_QPA_PLATFORM=xcb bash launch_gazebo.sh --render-engine ogre
```

新版小车启动入口已默认采用 xcb 和 Ogre，不要在排查时随意换回 Ogre2。

### 终端 1：地图＋小车

先关闭旧 Gazebo，避免同时运行多个相同世界。

```bash
cd ~/dongfeng_sandbox
bash launch_car.sh
```

它会依次：

1. 加载 `/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash` 并检查所需 ROS 包。
2. 调用 `scripts/build_control.sh` 编译两个包。
3. 将编译产物放入 `build_control/`、`install_control/`、`log_control/`，刷新 CMake 缓存。
4. 加载 `install_control/local_setup.bash`。
5. 启动世界、发布机器人描述、生成小车、启动控制节点与 ROS/Gazebo 桥接。

### 终端 2：键盘

```bash
cd ~/dongfeng_sandbox
bash keyboard_control.sh
```

保持这个终端处于焦点，切换英文输入法。长按移动键，不能在 Gazebo 窗口里按键来代替这个终端。

| 按键 | 功能 |
| --- | --- |
| W / I | 前进 |
| S / , | 后退 |
| A / J | 原地左转 |
| D / L | 原地右转 |
| U / O | 前进左转 / 前进右转 |
| M / . | 倒退并分别向负 / 正角速度方向转动 |
| 空格 / K | 发送零速停车 |
| + / - | 调速；调整速度时先停车 |
| Q / Ctrl+C | 停车并退出键盘程序 |

默认线速度 0.10 m/s，角速度 0.65 rad/s。终端无法直接读取松键事件，程序依靠按键重复超时：松键约 0.65 秒后发送零速，车体再按减速度停止。需要主动停车时按空格。方向键不支持，相关转义序列会触发停车并被过滤。

若提示缺少依赖，原工程 README 提供的安装命令为：

```bash
sudo apt update
sudo apt install ros-jazzy-ros-gz ros-jazzy-xacro \
  ros-jazzy-robot-state-publisher ros-jazzy-rclpy \
  ros-jazzy-geometry-msgs python3-colcon-common-extensions
```

上述命令仅在新环境确实缺包时执行。普通启动无需运行外形生成器，也无需安装建模软件。

## 6. 当前控制链路与设计依据

```text
键盘程序（ROS Twist）
  → ROS /cmd_vel
  → command_guard：限速、过滤非法数值、超时清零
  → ROS /cmd_vel_safe
  → ros_gz_bridge
  → Gazebo /cmd_vel
  → gz::sim::systems::DiffDrive
  → 左右两侧各两个车轮
```

### 驱动与坐标

- 沿用 Gazebo DiffDrive，不是 ros2_control，也没有自行实现 PID 或真实转向舵机控制。
- 当前是**四轮差速 / 滑移转向近似**；真实硬件驱动和转向方式尚未测量标定。
- 后轮保留旧关节名：`wheel_left_joint`、`wheel_right_joint`。
- 新增前轮：`wheel_left_front_joint`、`wheel_right_front_joint`。
- 四个轮子关节轴都为 `0 1 0`，车体 +X 向前、+Y 向左、+Z 向上。
- 正角速度对应左转；控制器给左、右轮的角速度分别为 `(v - w*b/2)/r`、`(v + w*b/2)/r`，这里 b=0.132 m、r=0.028 m。
- Gazebo 插件支持每侧多个关节；本工程已把四个实际关节都列入，而非仅给前后两轮做装饰。

### 速度与停车

- 键盘默认 0.10 m/s、0.65 rad/s。
- 速度上限为线速度 ±0.25 m/s、角速度 ±1.2 rad/s。
- Gazebo 加速度限制为线加速度 ±0.6 m/s²、角加速度 ±2.4 rad/s²。
- `command_guard` 每 0.02 秒发布一次，0.4 秒无新输入即清零；输入队列只保留最新指令。
- 键盘松键判断默认 0.65 秒；程序退出时尽量发送零速，守护节点继续负责输入失联后的清零。
- 守护节点使用单调墙钟和 STEADY_TIME 定时器。Gazebo 暂停时，超时计算不依赖停住的 `/clock`。
- launch 对守护节点退出设置了整体关闭处理；机器人生成失败也会结束启动。
- 这些措施不等于完整的硬件安全系统；例如桥接异常退出、仿真进程挂起等故障尚未在 Linux 端做过故障注入测试。

### 时间、话题与生成位置

- ROS 状态发布器与桥接默认 `use_sim_time=true`。
- 桥接的话题是 `/clock`、ROS `/cmd_vel_safe` → Gazebo `/cmd_vel`、`/odom`、`/tf`、`/joint_states`。
- 对外需要发速度时用 ROS `/cmd_vel`，持续发布至少 10 Hz 即可；不要绕过守护节点直接发 `/cmd_vel_safe`。
- `/odom` 是轮式里程计，原点相对启动位置；它不等于沙盘世界坐标，打滑时也不能替代真实位姿。
- 小车模型名为 `dongfeng_car`，出生位置为 `(1.65, 0.19, 0.031)` m，yaw=0。
- 生成时明确指定 SDF 内的世界名；车是独立动态实体，地图仍为静态实体。
- `GZ_SIM_RESOURCE_PATH` 包含地图模型目录和机器人安装包的 share 父目录，以解析网格资源。

**必须保留的高度修正：** AB 端是“高—低—高”，两侧圆弧最高 5 cm，中间横向直路保持 0；爬升发生在圆弧部分，不能再整体抬高前端直路。CD 升高如何分配允许近似，目前按直坡上升 6.5 cm、圆弧再上升 6.5 cm 处理。后续已将后方两处圆弧改为平滑高度曲线，入口内外侧均承接直坡坡度，出口逐渐变平，避免接头折角。

### 已完成的局部迭代

1. 根据照片和上述尺寸建立地图，包含道路、路缘、建筑、绿地、水池、树木、路灯、护栏等。
2. 修正 AB 端直路与圆弧高差。
3. 调整 AB 到中央路口的箭头、白线、斑马线。所谓“路面贴图”实际采用贴近路面的白色网格，不是整张照片纹理。
4. 重做 B 区高楼、连接体及 L 形低楼布局。
5. 调整两栋 L 形楼与湖的相对位置：两栋低楼在近端并排，湖移到后方，湖形更加细长并连接细水道。
6. 同伴后来刷新工程、微调地图并加入简化小车。当前 README 还记录了停车场开口与道闸等调整，应尊重当前文件，不能回退到早期地图。
7. 在此基础上完成照片版小车重建，再补齐当前键盘驾驶链路。

建筑、景观和道路未测部分按照片近似，用户接受误差。地图生成器内仍有一些固定坐标；不能仅改场地长宽，就假定所有对象都会自动按比例重排。

`config/scene/scene_config.json` 中“本项目不含小车”的历史句子描述的是静态场景生成范围，并不表示当前工程没有机器人包。不要因为这条旧文字而删除或重复添加小车。

## 9. 已做的验证，以及它们不能证明什么

### 有记录的结果

- 五方向小车浏览器预览完成，无浏览器脚本错误。
- URDF XML、网格引用、OBJ 索引与法向、GLB 结构、有限数值和非退化三角面检查通过。
- 四轮位置、轴向、半径、质量和惯量合法性、相机光学朝向检查通过。
- 出生范围 775 个地面采样点均为 z=0，四轮初始离地 3 mm。
- 11 项控制测试覆盖方向映射、松键超时、断开超时、调速上限、停车/退出、非法数值、时间回退、分段方向键序列及四轮配置。
- 控制与车辆阶段核对的 77 个原地图/压缩包文件保持不变。
- `validation_report.json` 中的“34 个安装文件一致”仅代表其当时实际检查范围，不是完整的 ROS 编译或依赖测试。

### Linux 上可复跑的检查

```bash
cd ~/dongfeng_sandbox
python3 src/dongfeng_bringup/test/test_control.py
python3 src/dongfeng_description/scripts/validate_vehicle.py
```

车辆验证的 `--scope-baseline` 当时引用外层 `tmp/vehicle_scope_before.json`，里面是 Windows 绝对路径。这个外层临时审计文件不是 Linux 正常运行依赖；新环境不要原样套用该参数。原 SHA-256 清单仅适用于整理前的迁移副本；当前目录应结合 Git 状态与现有验证脚本核对。

控制出生点审计脚本也曾在外层临时目录运行，最终结论写入 `reports/control/control_validation.json`。如果以后改出生点或地图，需要在新环境重新验证，不能沿用旧报告。

**仍未验证：** 最新小车在真实 Gazebo 进程中的网格加载、四轮稳定接触、实际平移/转向、爬坡、碰撞、失联停车时间、暂停恢复行为。静态检查和纯 Python 测试都不能替代这些验证。

## 10. Linux 接续时的建议排查顺序

1. 确认当前目录就是最新工程，读取本文与 README 第 8 节；不要先重建地图。
2. 确认 ROS 2、Gazebo 和依赖已安装，按 `launch_car.sh` 启动，保存本次实际错误。
3. 确认地图成功加载、实体树中有 `dongfeng_car`，小车位于 AB 直路中央并落地。
4. 打开键盘终端，先用默认低速试 W/S、A/D、空格，再试松键和退出。
5. 若不动，按“键盘输入 → ROS 输入速度 → 守护输出 → 桥接 → Gazebo 驱动关节”逐段定位，不要直接改地图几何。
6. 若轮子转而车不走，检查碰撞、关节、摩擦、车底是否卡住、仿真是否暂停；四轮滑移转向参数可能需要实际调节。
7. 若前进或转弯方向不对，核对 +X 车头、关节 +Y 轴、左右关节分组与正角速度约定。
8. 若贴图/网格丢失，核对机器人包安装目录与 `GZ_SIM_RESOURCE_PATH`；若界面闪烁，先确认仍为 xcb＋Ogre。
9. 如果报旧 CMake 路径，检查是否误用了旧的 `build/`、`install/`；推荐入口使用 control 目录并清缓存，不要求删除原资料。
10. 实际验证后，更新报告与本文“待验证”部分，明确区分修了什么、测了什么、哪些仍未测。

常用观察命令（启动后，在第三个终端）：

```bash
source /opt/ros/jazzy/setup.bash
source ~/dongfeng_sandbox/install_control/local_setup.bash
ros2 topic echo /cmd_vel --once
ros2 topic echo /cmd_vel_safe --once
ros2 topic echo /joint_states --once
ros2 topic echo /odom --once
ros2 run tf2_ros tf2_echo odom base_link
```

停止键盘输入时，观察守护输出归零。车体真正停止可能有减速过程；不得将“发布零速”和“瞬间物理静止”混为一谈。观察话题无消息时命令可能等待，应先确认对应节点已启动。
