# 综合巡航动态速度优化验收（2026-09-30 至 2026-10-01）

> 以下是两套速度模式和新绿灯周期规则仍存在时的历史验收。2026-10-03 起，当前启动入口仅保留优化后的快速参数，已有绿灯连续确认三帧后直接通行，不再要求等待一轮灯周期；当前用法以 README 为准。

工作区为 `feat/speed`，起始提交 `2f0dabd` 与 `origin/feat/slam` 一致。修改前工作区干净，直接基于已验证综合巡航实现优化。普通模式默认保留，运行 `bash launch_autonomy.sh driving_mode:=fast` 启用快速演示；`driving_mode:=normal` 回退。没有调整静态场景、碰撞网格、定位门限、人工锁存或信号通行规则。

## 策略与代码

- `speed.py` / `config/speed_fast.json`：按约 1.5 cm 弧长采样曲率、区域限速和段边界，向后传播 0.25 m/s² 的制动包络。实时预瞄 0.85 m，可跨尚未进入的任务段。横向加速度仍限制在原 0.045 m/s²，直道候选上限 0.40。
- `control.py`：按曲率、横向偏差、实际轮速、odom/IMU 年龄、前方停止线连续限制速度；正常行驶加速按仿真时间限制在 0.25 m/s²。停止线预留 3.5 cm 与至少 0.25 s 控制延迟，再增加实际姿态年龄。实际速度超出可停车包络时立即零指令。急停不受加速平滑器约束。
- 路段策略：中央北/南直道分别最多 0.24/0.32，路口 0.13–0.16，环岛 0.10–0.12，停车场 S 路线 0.14，左窄入口保留 0.075，右出口 0.09；坡道最多 0.18，倾角较大时 0.16；返程小弯 0.08。具体命令仍受曲率和安全条件压低。
- 跟踪沿用 pure pursuit 和现有 IMU yaw PI。直道前视随轮速增加，上限 0.22 m；特殊段维持现有短前视、路径走廊及完成条件。外围快速模式额外在回起点前软减速。
- 两级命令链和 DiffDrive 通过同一个 `driving_mode` 切换限幅。普通自动仍 0.20，普通 guard/模型仍 0.25；快速自动、guard、模型上限 0.40。人工始终最高 0.25。车辆摩擦、滑移、物理加速度及转向参数未改；车辆生成器同步维护 xacro 参数。
- 障碍保护反应预算快速模式为 0.60 s，使用规划目标与实际速度中的较大值，触发障碍停车后保持该制动包络，直到新鲜扫掠净空重新允许通行。视觉/定位低速档不会释放仍在原处的障碍；障碍移除后自动清除保持，并平滑加速。实跑发现起步斜坡曾导致障碍前反复启停，已修复并补连续阻塞回归；不以很小的起步指令重新宣布障碍可通过。
- `validate_run.py` / `evaluation.py` / `compare_speed_runs.py`：记录双时间尺度、真值速度、加减速、定位误差和分段统计；快速模式运动连续性检查按合法 0.40 m/s 上限核验，未改变走廊/碰撞门限。三处 `require_new_green` 信号逐个要求红停证据。受控测试授权过期后重新给红灯，驾驶器仍需图像观察新周期和三新帧。

## 功能复核

默认快速完整实跑没有 FAULT_STOP；保留一次左入口约 0.20 仿真秒的 OBSTACLE_STOP，实际间隙不足加强后的保守制动预算时主动停车，随后恢复。没有取消这项保护，也没有把这类短停计为信号等待。特殊段几何、三灯视觉 ROI、新周期要求、人工接管/恢复、传感器年龄和定位创新限制保持原有规则。

停车场普通/快速分别保存 569/481 帧扫描与 568/480 次局部匹配；已观测格 8717/8315（快速约为基准的 95.4%），地标数 4138/4161。PGM/YAML/NPZ 均可完整读取，局部 SLAM 有效。

在最后增加障碍停车保持逻辑前，另一自然灯相位 **+8 s 的实际 GUI 完整实跑通过**：整轮墙钟 359.79 s，仿真巡航 203.905 s，路径最大偏差 3.067 cm，返回距离 2.366 cm。GUI 探针记录的实际窗口灯色与三次绿灯越线判定均通过，三处红停和 SLAM 导出通过。此轮同时改变灯相位并开启 GUI，不能用其墙钟差值计算与 headless 基准的纯车速收益。

最终代码的受控信号完整巡航同样通过：墙钟 **264.34 s**、仿真巡航 **166.415 s**，三处红停/视觉新绿、19 段、碰撞、返回姿态和 SLAM 均通过。受控模式仅由验证器给出红灯至少 2 秒后转绿，驾驶器仍需原有观测授权；不能用此轮与自然相位基准计算提速百分比。

单元及回归：自主 **92/92**、bringup **18/18**；三个 ROS 包构建、模型 normal/fast 生成器回环以及 `git diff --check` 通过。独立代码审查发现的制动滞后、可取消裕度、障碍恢复和三灯验收遗漏均已补先失败后通过的测试。

最终代码另通过 **21/21 故障场景**：人工接管锁存/倒车/重启、图像和雷达断流与旧帧、无效雷达显式恢复、直道与弯道真实碰撞障碍及移除恢复、仿真暂停恢复、时钟回退锁存、驾驶节点退出联动关闭。该套现有脚本的注入速度较低，因此另外实施独立高速复测；不把低速回归当作高速制动证据。

## 耗时瓶颈与观察项

车辆行驶墙钟从 310.26 s 减少至 240.90 s；信号等待却从 63.49 s 增至 86.92 s。提早到达时仍严格等待新的红→绿周期，部分速度收益被相位等待抵消。保留该视觉安全规则。

两次仿真实时因子约 0.64，相同仿真动作在虚拟机上约需 1.56 倍墙钟时间。Ogre2 软件传感器渲染及虚拟机性能是剩余瓶颈，提速不会消除；本次未降低相机/雷达分辨率或频率，也没有放宽新鲜度。最终自然轮返回航向误差为 3.91°，受控轮为 14.39°，后者接近原有 15° 完成上限但仍通过；没有放宽该门限。左入口的小余量、坡顶接触姿态、最终返程姿态和高速度视觉观感仍建议现场人工观察；自动碰撞与窗口灯色检查已经完成。结果适用于当前 Gazebo 模型与机器环境，实车需要重新标定制动距离、轮地附着和传感器时延。
